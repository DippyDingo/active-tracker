# Быстрый старт по репозиторию

REDIS — десктопное приложение Windows для учёта времени в других программах. Это не библиотека и не сервис: один процесс с графическим интерфейсом на PySide6, хранящий статистику в SQLite и умеющий обновлять сам себя.

Эта страница — карта. Найдите свою задачу и перейдите к нужной странице.

## Что нужно знать до начала

Приложение работает в одном процессе и делает три вещи одновременно:

1. Раз в секунду спрашивает у Windows активное окно и время простоя, начисляя время приложениям из списка.
2. Показывает статистику в окне с собственным оформлением.
3. Периодически проверяет GitHub на новую версию и умеет тихо обновляться через отдельный процесс.

Технические требования: Python 3.13, Windows 10/11, зависимости из `requirements.txt` (PySide6, pywin32, Pillow, psutil). Запуск из исходников — `python main.py`.

## Правила, которые легче всего нарушить

Собранные здесь ограничения повторяются в комментариях кода и подтверждаются историей исправлений. Нарушение любого из них приводило к реальному сбою.

### Про учёт

- **Дробные секунды переносятся.** Округление при начислении даёт систематическую потерю времени.
- **При ошибке записи буфер сохраняется.** Очистка в `except` — потеря данных.
- **Один тик начисляет не больше 7 секунд.** Ограничение защищает от скачков времени и приостановки процесса.
- **`flush()` перед сменой базы обязателен** — иначе накопленное уйдёт в новую базу, хотя относится к старой.

### Про данные

- **Запись через `.part` и переименование.** Прямая запись в целевой файл ломает гарантию целостности.
- **Перед копированием — `wal_checkpoint(TRUNCATE)`.** Иначе копия может не содержать последних записей.
- **`has()` и `get_int()` различаются.** Отсутствие ключа и значение 0 требуют разных действий.
- **Новая колонка требует ветки в `_migrate()`.** Дописать в `_SCHEMA` недостаточно — старые базы её не получат.

### Про обновление

- **Проверка установки идёт до захвата мьютекса.** Иначе приложение ждёт само себя.
- **Маркер установки снимается до запуска новой версии.** Обратный порядок оставляет пользователя без приложения.
- **`mark_clean_exit` обязателен.** Без него любое закрытие окна считается падением.
- **Стратегия B: только установщик.** Голый exe не скачивается никогда.
- **Нет кэша отката — нет отката.** Это защита от бесконечного цикла.

### Про интерфейс

- **`QApplication` создаётся один раз и до диалогов.**
- **Значения на экране = база + `pending_seconds`.** Без второго слагаемого интерфейс отстаёт до 15 секунд.
- **`_COLOR_CACHE` очищается при смене темы.** Иначе окно перекрашивается частично.
- **Бесконечных анимаций нет.** Они жгут CPU при простое.
- **`wait_workers` остаётся подписанной на выход.** Иначе `QThread` уничтожается на ходу.

### Про имена-наследство

Приложение переименовано из Nodexy в REDIS, но несколько имён сохранено сознательно:

| Имя | Где | Почему |
|---|---|---|
| `NodexySingleInstanceMutex` | мьютекс | Совпадает с `AppMutex` установщика |
| `Nodexy` | значение `HKCU\...\Run` | Установщик пишет в него же |
| `ActiveTracker` | каталог данных | Смена «потеряла» бы статистику |
| `nodexy.lock`, `nodexy_update.log` | файлы | Внутренние имена |

Менять любое из них можно только вместе с миграционным планом.

## Как менять версию

Единственный источник — `app/version.py`. Из него выводятся файл версии для PyInstaller, имя установщика и проверка соответствия тегу в CI. Тег без поднятия `APP_VERSION` уронит сборку релиза — это сделано намеренно.

## Куда смотреть при сбое

- `%APPDATA%\ActiveTracker\crash.log` — ошибки Python и фатальные сбои.
- `%APPDATA%\ActiveTracker\nodexy_update.log` — работа помощника обновления.
- `%APPDATA%\ActiveTracker\nodexy_install.log` — журнал установщика Inno.
- `%APPDATA%\ActiveTracker\config.json` — состояние обновления и запуска.

Подробнее — [Конфигурация и журналы](data/config-and-logs.md).
