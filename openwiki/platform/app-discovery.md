# Обнаружение установленных приложений

Чтобы отслеживать программу, её сначала нужно добавить в список. Вручную вписывать путь к exe неудобно, поэтому приложение сканирует систему и предлагает найденное. Сканирование — самая эвристичная часть кода: здесь нет единого API Windows, который ответил бы на вопрос «какие программы установлены», поэтому источников четыре, и каждый покрывает то, чего не видят остальные.

## Четыре источника

`get_installed_apps()` собирает результаты из четырёх функций и объединяет их:

| Источник | Функция | Что находит | Что пропускает |
|---|---|---|---|
| Реестр Uninstall | `_registry_apps` | Программы с установщиком | Портативные, игры Steam |
| Меню Пуск | `_start_menu_apps` | Ярлыки `.lnk` | Программы без ярлыка |
| Steam | `_steam_games` | Игры из библиотек Steam | Остальное |
| Запущенные процессы | `_running_apps` | Всё, что работает сейчас | Ничего не запущено — пусто |

Дедупликация выполняется по нормализованному пути: `os.path.normcase(app.exe_path)` как ключ словаря, и первая встреченная запись побеждает. Порядок конкатенации — реестр, меню Пуск, Steam, процессы. Это задаёт приоритет: запись из реестра имеет лучшее имя и иконку, поэтому она выигрывает у записи из процессов.

Итоговый список сортируется по имени без учёта регистра.

## Реестр Uninstall

Источник читает три корня:

```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall
HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall
HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall
```

Два первых нужны из-за раздельного хранения 64- и 32-битных программ, третий — для установок только для текущего пользователя.

Для каждой подзаписи `_read_entry` применяет фильтры. Запись отбрасывается, если:

- нет `DisplayName`;
- `SystemComponent = 1` — служебный компонент, не программа;
- есть `ParentKeyName` или `ParentDisplayName` — это обновление или дополнение к другой программе;
- имя содержит маркеры обновлений: `update for`, `hotfix`, `security update`, а также русские «накопительное обновление», «обновление для», «обновление microsoft».

Далее определяется путь к exe — и это самая нетривиальная часть, потому что реестр не хранит его напрямую. Используются три попытки по убыванию надёжности:

1. **`DisplayIcon`**, если он указывает на существующий `.exe` и не похож на деинсталлятор. Это самый точный вариант: обычно там именно главный файл программы.
2. **Каталог `DisplayIcon`** — если иконка лежит рядом с exe, берётся главный exe из этой папки через `_pick_main_exe`.
3. **`InstallLocation`** — если предыдущие не дали результата, главный exe ищется в каталоге установки.

`_pick_main_exe` тоже эвристика:

- список `.exe` в каталоге фильтруется от деинсталляторов (`_looks_like_uninstaller` проверяет префиксы `unins`, `uninst`, `unwise`, `unreg`, `uninstall`, `remove`);
- если остался один кандидат — он и есть главный;
- иначе предпочитается файл, имя которого совпадает с именем папки (например `Photoshop\Photoshop.exe`);
- иначе берётся самый большой по размеру — обычно это и есть приложение, а не вспомогательная утилита.

Если exe найти не удалось, запись отбрасывается полностью: приложение без пути отслеживать невозможно.

## Меню Пуск

`_start_menu_apps` обходит два корня — общий `%PROGRAMDATA%\Microsoft\Windows\Start Menu\Programs` и пользовательский `%APPDATA%\...\Programs` — и разбирает ярлыки `.lnk` через COM-объект `WScript.Shell`.

Ключевая деталь — работа с COM: перед использованием вызывается `pythoncom.CoInitialize()`, а в `finally` — `CoUninitialize()`. Без инициализации COM-вызовы в рабочем потоке могли бы вести себя непредсказуемо. Если импорт `pythoncom` или `win32com.client` не удался, функция возвращает пустой список, а не падает: остальные источники продолжат работу.

Из ярлыка берётся `TargetPath`. Он принимается, только если:

- оканчивается на `.exe`;
- файл действительно существует;
- это не деинсталлятор.

Именем программы становится имя файла ярлыка без расширения — так пользователь видит в списке то же название, что и в меню Пуск.

## Steam

`_steam_games` решает задачу, до которой реестр и меню Пуск не добираются: игры Steam не регистрируются в Uninstall и часто не имеют ярлыков.

Последовательность:

1. Путь Steam берётся из `HKCU\SOFTWARE\Valve\Steam`, значение `SteamPath`. Если его нет — источник ничего не возвращает.
2. Из `steamapps\libraryfolders.vdf` регулярным выражением достаются все пути библиотек: `"path"\s+"([^"]+)"`. Это позволяет находить игры не только в основной библиотеке, но и на других дисках.
3. Если файл не читается, используется сам каталог Steam как единственная библиотека.
4. В каждой библиотеке перебираются `appmanifest_*.acf`. Из них извлекаются `"name"` и `"installdir"`.
5. Каталог игры — `steamapps\common\<installdir>`, главный exe выбирается через `_pick_game_exe`.

`_pick_game_exe` отличается от `_pick_main_exe` набором исключений: помимо деинсталляторов, отбрасываются `setup`, `redist`, `vcredist`, `directx`, `dxsetup`, `launcher`, `crash`, `report`, `cleanup`, `configure`, `dotnet`, `ue4-prereq`. Игры часто содержат лаунчеры и установщики библиотек рядом с основным exe, и без этого фильтра в список попал бы `UnityCrashHandler.exe`.

Приоритет: сначала точное совпадение `<имя игры>.exe`, затем отфильтрованный пул, отсортированный по размеру.

## Запущенные процессы

`_running_apps` — единственный источник, который находит портативные программы без установки. Он перебирает процессы через `psutil` и отбрасывает:

- процессы без пути к exe или с несуществующим файлом (системные процессы без прав доступа);
- всё, что лежит в `%SystemRoot%` — исключение по префиксу пути, а не по имени: так отсеиваются системные утилиты;
- деинсталляторы;
- три конкретных имени: `explorer.exe`, `searchhost.exe`, `applicationframehost.exe`. Они всегда запущены и не являются «приложениями» в смысле учёта.

Имя берётся из `FileDescription` ресурсов exe, а при его отсутствии — из имени файла без расширения. Та же функция `get_file_description` используется в Win32-слое и умеет читать локализованные описания.

## Где это используется в интерфейсе

Сканирование выполняется не в главном потоке. В `app/ui/add_dialog.py` есть `_ScanWorker` (`QThread`), который вызывает `get_installed_apps()` и отдаёт результат сигналом. Пока скан идёт, панель показывает прогресс.

Иконки загружаются отдельно и асинхронно: `_IconTask` — это `QRunnable`, выполняемый в пуле потоков. Для каждого найденного приложения иконка извлекается через `extract_icon_png` и конвертируется в PNG. Причина разделения проста: извлечение иконки — дорогая Win32-операция (создание bitmap, отрисовка, кодирование PNG), и делать её синхронно для сотни программ означало бы заморозку интерфейса на секунды.

Порядок важен: список показывается сразу, а иконки подставляются по мере готовности.

Отдельно есть `wait_workers(timeout_ms=8000)`, которую `main.py` подписывает на `aboutToQuit`. Она дожидается завершения фоновых потоков перед выходом. Без этого Qt уничтожил бы работающий поток, что даёт «QThread destroyed while running» и потенциальную порчу памяти.

## Ограничения подхода

Эвристики неизбежно дают промахи, и это стоит понимать при работе с этим кодом:

- **Игра с лаунчером.** Если основной exe игры — `Launcher.exe`, а сама игра — отдельный процесс, будет добавлен лаунчер. Учёт времени в игре при этом окажется неполным.
- **Программа с несколькими exe.** Выбор по размеру может указать на вспомогательный компонент, а не на то, что пользователь запускает.
- **Уникальность по пути.** Одно приложение, установленное в две папки, даст две записи — это следствие дедупликации по пути, а не по имени.
- **Портативные без запуска.** Программа, которая не установлена и не запущена, не будет найдена. Для таких случаев в панели добавления есть ручной выбор файла.

Поэтому обнаружение — это подсказка, а не окончательный ответ: пользователь всегда может выбрать exe вручную.

## Что важно помнить при правке

- Порядок конкатенации источников задаёт приоритет. Перестановка изменит то, какое имя и иконка попадут в список.
- `_looks_like_uninstaller` работает по префиксу, а не по вхождению: файл `Uninstaller.exe` отбрасывается, но `MyUninstallManager.exe` — нет (он начинается с `my`).
- COM-инициализация в меню Пуск обязательна, и её нужно парно освобождать.
- Любая новая эвристика должна сохранять свойство «нет exe — нет записи».
- Сканирование и загрузка иконок выполняются в фоновых потоках, и `wait_workers` должна оставаться подписанной на выход приложения.
