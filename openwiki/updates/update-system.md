# Проверка обновлений и загрузка релиза

Первая половина подсистемы обновления — от вопроса «есть ли новая версия» до появления готового к установке файла. Здесь нет работы с файлами приложения, но есть свои тонкости: версии сравниваются не строками, ассеты выбираются по имени, а загрузка защищена от гонок.

## Сравнение версий

Версия не может сравниваться как строка: `"1.10.0" < "1.9.0"` лексикографически, хотя семантически наоборот. Поэтому версия разбирается в кортеж чисел.

`parse_version(text)` применяет регулярное выражение `^\s*v?(\d+(?:\.\d+)*)`, то есть принимает необязательный префикс `v` и последовательность чисел через точку. Возвращает кортеж целых или `None`, если строка не похожа на версию.

`_norm(a, b)` выравнивает длины кортежей нулями до одинакового размера:

```python
n = max(len(a), len(b))
return a + (0,) * (n - len(a)), b + (0,) * (n - len(b))
```

Без выравнивания `(1, 2)` и `(1, 2, 0)` сравнивались бы как разные кортежи, хотя обозначают одну версию. С выравниванием они равны.

Две функции поверх этого:

- `is_newer(candidate, current)` — строгое сравнение `a > b`;
- `same_version(a, b)` — сравнение на равенство, учитывающее префикс `v` и разную длину (`v1.2` == `1.2.0`).

`same_version` используется при разборе `update_pending`: если версия в ожидании совпадает с текущей, значит обновление применилось.

Если версия не разбирается (например, тег вида `release-latest`), функции возвращают `False` — не навязывать обновление по нераспознанному тегу безопаснее.

## Получение релизов

`fetch_releases()` запрашивает `RELEASES_URL` — это `https://api.github.com/repos/DippyDingo/active-tracker/releases?per_page=20`.

Запрос собирается через `urllib.request.Request` с двумя заголовками:

- `User-Agent: Nodexy` — GitHub API требует `User-Agent` и отклоняет запросы без него;
- `Accept: application/vnd.github+json`.

Таймаут — `HTTP_TIMEOUT = 25` секунд. Результат приводится к списку; если API вернул не список, возвращается пустой список.

Запрос выполняется в фоновом потоке `CheckTask` (наследник `QThread`), который испускает либо `ok(releases)`, либо `error(message)`. Синхронный запрос в главном потоке заморозил бы интерфейс на время до 25 секунд.

## Выбор релиза

`select_update(releases, current)` выполняет отбор:

1. Каждый релиз разбирается через `parse_release`.
2. **Отбрасываются** черновики (`draft`) и предварительные версии (`prerelease`) — стабильность важнее свежести.
3. **Отбрасываются** релизы, чей тег не разбирается в версию.
4. **Отбрасываются** релизы без подходящего ассета (`asset_url is None`) — это ключевое место, см. ниже.
5. Оставшиеся сортируются по версии по убыванию.
6. Если последний не новее текущей, возвращается `(None, "")` — обновления нет.

### Стратегия B: только установщик

Константа `PREFER_INSTALLER_ASSET = True` включает режим, который в коде назван стратегией B.

`_pick_asset(assets, prefer_installer)` делит все `.exe`-ассеты на две группы по имени:

```python
def is_installer_asset(name: str) -> bool:
    n = (name or "").lower()
    return any(marker in n for marker in
               ("-setup", "_setup", "setup-", "-installer", "installer"))
```

- **установщики** — содержат один из маркеров (`REDIS-Setup-1.4.3.exe`);
- **прочие** — всё остальное (`REDIS.exe`).

При `prefer_installer=True` кандидатами становятся **только** установщики. Если их нет, возвращается `(None, None, None)`.

Почему запасного варианта нет, объясняет комментарий: иначе апдейтер скачал бы голый exe и попытался «обновиться» им поверх установленной копии. Это разрушило бы раскладку `--onedir` (exe плюс папка `_internal`) и оставило бы установку в несогласованном состоянии.

Поэтому релиз без установщика считается непригодным для автообновления целиком — не «обновился чем-то другим», а «обновления нет».

При `prefer_installer=False` (устаревший механизм) приоритет обратный: голый exe предпочтительнее, установщик — только если exe нет.

### Извлечение SHA256

`parse_sha256(text)` ищет сумму в теле релиза двумя способами:

1. По явной метке: `(?:sha\s*256|sha256)[^\w]{0,3}([0-9a-fA-F]{64})`.
2. По любому 64-символьному hex-значению в тексте.

Первое правило точнее, второе — запасное. В сборке `release.yml` в тело релиза пишется ровно одна строка `sha256: <сумма>`, поэтому первое правило всегда срабатывает.

## Заметки к обновлению

Если пропущено несколько версий, в окне «Что нового» нужно показать изменения всех, а не только последней.

`select_update` собирает `newer` — все релизы новее текущей версии. При одном релизе берётся его `body`. При нескольких формируется объединение: для каждого релиза берётся заголовок и тело, причём если тело уже начинается с тега, тег не дублируется.

## Загрузка

`DownloadTask` (наследник `QThread`) скачивает установщик с сигналами `progress(got, total)`, `ok(path)`, `error(message)`.

### Блокировка параллельных загрузок

Это защита от конкретного сбоя, описанного в комментарии: автоскачивание в тихом режиме и ручная кнопка «Скачать и установить» писали в один и тот же `*.part` и портили друг друга.

Реализация — набор занятых путей с мьютексом:

```python
_DOWNLOAD_LOCKS: dict[str, int] = {}
_DOWNLOAD_LOCK_GUARD = threading.Lock()

def claim_download(dest) -> bool: ...
def release_download(dest) -> None: ...
```

`DownloadTask.run` начинается с `claim_download(dest)`. Если путь уже занят, задача немедленно завершается с ошибкой `"already-downloading"`. Освобождение — в `finally`, поэтому отмена и ошибка не оставляют путь навсегда занятым.

### Процесс скачивания

1. Целевой временный файл — `dest + ".part"`.
2. Запрос с `User-Agent: Nodexy`, таймаут 60 секунд.
3. Чтение блоками по 65536 байт с записью на диск и испусканием прогресса.
4. `os.replace(tmp, dest)` — атомарное переименование по завершении.
5. При отмене (`_cancel`) выбрасывается `InterruptedError`, временный файл удаляется, испускается `"cancelled"`.
6. При ошибке временный файл тоже удаляется.

Схема с `.part` и `os.replace` даёт ту же гарантию, что и в работе с базой: по целевому пути либо старый файл, либо полный новый, но не половина.

## Проверка целостности

`verify_file(path, expected_size, expected_sha)` проверяет три условия:

1. Файл существует и является файлом.
2. Размер совпадает с ожидаемым, если он известен.
3. `sha256_file(path)` совпадает с ожидаемой суммой, если она известна.

`sha256_file` читает файл блоками по 65536 байт — не загружая 50-мегабайтный установщик в память целиком.

Проверка выполняется до планирования установки: неверная сумма означает повреждённую загрузку, и устанавливать её нельзя.

## Отложенное обновление и «Что нового»

Состояние хранится в `config.json`:

- `update_pending` — скачанное и ожидающее применения;
- `last_update` — применённое, с заметками и флагом `seen`.

`cancel_pending()` не только удаляет запись, но и **удаляет сам файл установщика** — иначе отменённое обновление оставляло бы десятки мегабайт в каталоге данных.

`mark_whatsnew_seen(version)` ставит `seen: true`, только если версия совпадает, — это защита от пометки чужих заметок. `whatsnew_unseen()` возвращает истину, пока заметки не просмотрены; по этому признаку главное окно показывает пункт «Что нового».

## Отложенное всплывающее предложение

`make_snooze(version, now)` формирует строку `"<версия>|<дата>"`, а `snooze_active(value, version, now)` проверяет:

- версия в строке совпадает с предлагаемой;
- с даты прошло меньше `SNOOZE_DAYS = 3`.

Привязка к версии важна: если пользователь отложил обновление до 1.4.3, а вышла 1.4.4, предложение должно появиться снова. Без проверки версии откладывание действовало бы на любое обновление.

## Что важно помнить при правке

- Версии сравниваются кортежами с выравниванием нулями, а не строками.
- Стратегия B: релиз без установщика означает «обновления нет», а не «скачаем что найдём». Голый exe не скачивается никогда.
- `claim_download` / `release_download` — обязательная пара; освобождение должно быть в `finally`.
- Загрузка идёт в `.part` с атомарным `os.replace`.
- `cancel_pending` удаляет файл, а не только запись о нём.
- Откладывание привязано к версии; проверка `parse_version(snoozed_version) != parse_version(version)` не должна убираться.
- Сетевые операции выполняются в `QThread`, а не в главном потоке.
