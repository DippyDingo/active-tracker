# Панель статистики и периоды

Панель статистики открывается по щелчку на карточке или строке боковой панели. Она показывает детальный график по выбранному периоду, суммарное время и возможность выделить произвольный диапазон.

## Пять периодов

Периоды определены в `app/utils.py` двумя параллельными списками:

```python
PERIOD_KEYS = ["day", "week", "month", "year", "all"]
PERIOD_TITLES = ["Сегодня", "Неделя", "Месяц", "Год", "Всё время"]
```

Индексы совпадают, поэтому переключатель и панель статистики используют одно и то же число для обозначения периода. Это единственный контракт между главным окном и панелью.

Дополнительно в панели есть `PERIOD_CAPTIONS` — формы для подписи «Статистика за …».

## Якорь периода

Панель хранит не «сегодняшнюю дату», а `_anchor` — точку отсчёта. Навигация кнопками «назад» и «вперёд» сдвигает именно её через `_shift_anchor(direction)`.

При смене периода якорь нормализуется:

```python
self._anchor = self._period_start(self._anchor)
```

`_period_start(d)` возвращает начало периода, в который входит дата:

- для дня — сама дата;
- для недели — понедельник через `week_start`;
- для месяца — первое число;
- для года — 1 января.

Это позволяет переключаться между периодами, не теряя позицию: если пользователь смотрел март, переключение на «Год» откроет год, содержащий март.

Кнопка «вперёд» отключается, когда якорь дошёл до текущего периода:

```python
self._next_btn.setEnabled(self._period_start(self._anchor) < self._period_start(self._today))
```

Кнопки навигации скрываются для периода «всё время» — там некуда двигаться.

## Построение ряда значений

`_series_for()` возвращает кортеж из пяти элементов: значения, подписи оси, тексты подсказок, единицу измерения и подпись периода.

### День

Значения — 24 числа из `_hours_for(a)`, то есть почасовое распределение за конкретный день. Подписи оси — часы от `00` до `23`. Подсказки — интервалы вида `08:00-09:00`, причём последний корректно заворачивается: `(h + 1) % 24`.

### Неделя

Семь дней от понедельника. Подписи оси — сокращённые названия дней недели из `WEEKDAYS`, что позволяет сразу узнать, где выходные.

### Месяц

Число дней берётся из `month_days(a.year, a.month)`, поэтому февраль в високосный год даёт 29 столбцов. Подписи оси — номера дней.

### Год

Здесь агрегация иная: значения не запрашиваются по одному дню, а суммируются из уже загруженной истории:

```python
for day_str, secs in self._history.items():
    if day_str.startswith(f"{a.year:04d}-"):
        totals[int(day_str[5:7]) - 1] += secs
```

Двенадцать столбцов по месяцам. Такой подход работает потому, что `_history` уже содержит всю историю приложения в памяти — запрашивать базу 365 раз было бы расточительно.

### Всё время

Самый сложный режим. Он возвращает пустые списки и единицу `"timeline"`, потому что ряд строится отдельно в `_set_period` через `TimelineData`.

Границы вычисляются так:

1. Первая дата — минимальная из истории.
2. Учитывается `_first_day` (дата первого запуска из конфига), если она раньше.
3. Но не позже сегодняшнего дня.
4. **И не позже, чем 30 дней назад** — то есть слева всегда добавляется минимум месяц пустого пространства.
5. Последняя дата — сегодня плюс 30 дней, чтобы справа тоже был запас для прокрутки.

Добавление пустых полей по краям — не косметика: график с прокруткой без запаса не даёт увидеть начало и конец данных, потому что крайние точки оказываются вплотную к границе.

## Ленивая загрузка почасовых данных

`TimelineData` — отдельный класс, решающий проблему объёма: за всё время работы в базе могут быть сотни тысяч почасовых записей, и загружать их разом нельзя.

Устройство:

- `_daily` — суточные значения, уже известные из `_history`;
- `_hours_cache` — кеш почасовых данных по дням: `{day_str: [24 значения]}`;
- `_total_hours` — общее число часов в диапазоне.

Ключевые методы:

- `_get_hours_for_day(day)` — возвращает почасовой ряд для дня, **запрашивая базу только при промахе кеша**;
- `get_value_at_hour(hour_idx)` — значение по абсолютному индексу часа: переводит индекс в день и час, затем обращается к кешу;
- `get_day_value(day)` — суточное значение;
- `load_hours_range(start_hour, end_hour)` — предзагрузка диапазона часов.

`load_hours_range` вызывается графиком, когда пользователь прокручивает или расширяет окно: вместо загрузки всей истории запрашивается только видимый участок.

Для «сегодня» почасовые данные дополняются живыми секундами из буфера трекера — `_today_live` передаётся в конструктор и учитывается при формировании сегодняшнего дня.

## Живые секунды сегодняшнего дня

Самая легко упускаемая деталь. Сегодняшний день существует в двух состояниях: то, что уже записано в базу, и то, что ещё лежит в буфере трекера и не сброшено.

Панель получает `tracker` и использует `_hours_for(d)` и `_day_value(d)`, которые для сегодняшней даты добавляют незаписанное время. В `TimelineData` то же самое делает `_today_live`.

Следствия:

- **Год**: `totals[self._today.month - 1] += self._today_live` — живое время прибавляется к текущему месяцу.
- **Неделя и месяц**: живые секунды попадают в сегодняшний столбец.
- **День**: почасовой ряд содержит живое время в текущем часе.

Без этого панель отставала бы от карточек главного окна до 15 секунд — на время между сбросами буфера.

## Итог и анимация

Суммарное значение вычисляется по-разному в зависимости от режима:

- для обычных периодов — `sum(values)`;
- для «всё время» — сумма `get_day_value(d)` по всем дням диапазона, но только до сегодняшнего дня включительно.

Последнее ограничение важно: диапазон простирается на 30 дней вперёд, и без фильтра `if d <= self._today` в сумму попали бы будущие дни, которых ещё нет, но которые технически входят в диапазон.

`_animate_big(value)` анимирует отображение, `_big_anim` останавливается перед новым запуском.

## Выделение диапазона

`_on_range_selection(sel)` получает от графика кортеж `(начало, конец)` в индексах или `None`.

При отсутствии выделения показывается `NO_SELECTION_HINT` — подсказка о том, как выделить диапазон, — и кнопка сброса скрывается.

При наличии выделения вычисляются суммы за выбранный участок и обновляется результат. Кнопка `_result_clear` позволяет снять выделение.

## Форматирование

Форматирование вынесено в `app/utils.py` и различает два регистра использования.

### Полная форма

`format_seconds(total)` возвращает человекочитаемую строку:

- «N ч M мин», если есть часы;
- «N мин SS с», если есть только минуты;
- «N с» иначе.

Используется в подсказках и подробных местах.

### Компактная форма

`format_compact(total)` — «Nч MMм», «Nм» или «Nс». Используется там, где места мало: в карточках и крупных значениях панели.

### Русские даты

Форматирование дат требует падежей, поэтому в модуле три параллельных массива:

- `MONTHS_GEN` — родительный падеж («января») для конструкций «5 января»;
- `MONTHS_NOM` — именительный («Январь») для заголовков;
- `SHORT_MONTHS` — сокращения («Янв») для оси графика.

`WEEKDAYS` — сокращённые названия дней недели, начиная с понедельника.

Функции: `label_day(d, today)` добавляет префиксы «Сегодня ·» и «Вчера ·»; `label_week(start)` выбирает формат в зависимости от того, пересекает ли неделя границу месяца или года; `label_month`, `label_year`, `ru_date`, `ru_date_short`.

### Арифметика дат

`add_months(year, month, delta)` переводит год и месяц в единый индекс (`year * 12 + month - 1`), сдвигает и раскладывает обратно. Это обходит проблему перехода через границу года без отдельных проверок.

`month_days(year, month)` использует `calendar.monthrange` — так получается правильное число дней, включая февраль в високосный год.

## Что важно помнить при правке

- Живые секунды сегодняшнего дня нужно добавлять во всех режимах; забыть один — значит показать разные числа на карточке и в панели.
- В режиме «год» данные агрегируются из `_history` в памяти, а не запросами к базе: 365 запросов были бы неоправданно дороги.
- В режиме «всё время» сумма ограничивается сегодняшним днём, иначе будущие дни диапазона попадут в итог.
- `TimelineData` загружает почасовые данные лениво; замена на полную загрузку сломает производительность на больших базах.
- Якорь нормализуется при смене периода — это сохраняет позицию пользователя.
- Запас по 30 дней с обеих сторон в режиме «всё время» нужен для прокрутки.
- Формы месяцев различаются по падежам; нельзя заменять `MONTHS_GEN` на `MONTHS_NOM` без потери грамматики.
