# Темы и оформление

Оформление в REDIS построено на трёх уровнях: `Palette` описывает цвета темы, `_derive` порождает из них производные токены, а шаблон QSS собирается в готовую строку стилей. Плюс параллельно существует `QPalette` — потому что QSS покрывает не всё.

## Palette

Тема — это неизменяемый (`frozen`) датакласс с фиксированным набором полей:

```python
@dataclass(frozen=True)
class Palette:
    key: str
    title: str
    bg: str
    bg2: str
    sidebar: str
    card: str
    card_hover: str
    border: str
    text: str
    text2: str
    text3: str
    accent: str
    cyan: str
    danger: str
    popup: str
    overlay: tuple
    shadow: tuple
    chart_fill_top: int
    chart_fill_bottom: int
    is_light: bool = False
```

Поля делятся на группы:

- **Фоны**: `bg`, `bg2` (градиент главного окна), `sidebar`, `card`, `card_hover`.
- **Границы и текст**: `border`, `text` (основной), `text2` (вторичный), `text3` (приглушённый).
- **Акценты**: `accent`, `cyan`, `danger` (для деструктивных действий).
- **Специальное**: `overlay` и `shadow` — кортежи RGBA, `chart_fill_top` и `chart_fill_bottom` — альфы заливки графика.
- **`is_light`** — переключатель, влияющий на производные цвета.

Все палитры собраны в словарь `PALETTES` с ключом по полю `key`. Тема по умолчанию — `DEFAULT_THEME = "redis"`.

Неизменяемость палитры важна: она гарантирует, что тема не будет случайно изменена по ходу работы. Смена темы — это замена ссылки `_current`, а не мутация объекта.

## Производные токены

Ручное перечисление всех цветов в QSS было бы неподъёмным: у виджета могут быть состояния (обычное, наведение, нажатие, отключено), и каждому нужен оттенок. Поэтому `_derive(p)` порождает около сорока токенов из базовых полей.

### Смешивание

Основной инструмент — `_mix_hex(a, b, t)`, линейная интерполяция между двумя цветами. Из неё получаются:

| Токен | Формула | Назначение |
|---|---|---|
| `sidebar_edge` | `border` → `bg`, 0.55 | Мягкая граница сайдбара |
| `card2` | `card` → `bg`, 0.35 | Второй уровень карточек |
| `card_border` | `border` → `card`, 0.45 | Граница карточки |
| `hover_border` | `accent` → `border`, 0.65 | Граница при наведении |
| `popup2` | `popup` → `bg`, 0.5 | Вторая поверхность попапа |
| `menu_text` | `text` → `text2`, 0.55 | Текст меню |
| `disabled_text` | `text3` → `bg`, 0.4 | Отключённый текст |

Принцип: оттенок для конкретного состояния не задаётся вручную, а выводится сдвигом к фону или к акценту. Это позволяет добавлять новые состояния без новой палитры.

### RGB-строки

Помимо hex-значений, генерируются строки вида `"r,g,b"` для `accent`, `danger` и `cyan`. Они нужны для `rgba(...)` в QSS, где альфа указывается отдельно от цвета.

### Полупрозрачные слои

`soft(pct)` собирает `rgba(...)` из двух частей:

```python
soft_rgb = "30,41,59" if p.is_light else "255,255,255"
```

На тёмных темах полупрозрачные слои — белые, на светлых — тёмные. Без этой инверсии подсветка на светлой теме выглядела бы выбеленной, а не выделенной.

Генерируется шесть уровней: `soft2`, `soft3`, `soft4`, `soft5`, `soft6`, `soft8` — от почти невидимого до заметного.

### Градиенты кнопок

`_button_colors(p)` возвращает четыре цвета: верх и низ обычной кнопки, верх и низ при наведении. Они используются и для обычных кнопок, и для кнопки добавления (`add_btn_*`).

## Почему QSS собирается на каждую тему

`build_qss(p)` — это `_QSS_TEMPLATE.safe_substitute(_derive(p))`.

Шаблон — это `string.Template`, а не f-строка, потому что подстановка идёт по именам вида `$token`. `safe_substitute` выбран намеренно: если в шаблоне встретится `$` без соответствующего ключа, он останется как есть, а не вызовет исключение. Это делает шаблон устойчивым к знаку доллара в комментариях и значениях.

Сборка на каждую тему, а не одна строка с переменными, — потому что QSS не поддерживает пользовательские переменные. Все значения должны быть подставлены заранее. Стоимость сборки невелика (шаблон около тысячи строк, подстановка — простая операция), а происходит она только при смене темы.

## Две системы цветов

Здесь кроется главная тонкость темизации, и в докстроке `build_palette` она объяснена прямо.

QSS покрывает не всё. Нативные элементы — фон прокручиваемой области (`QScrollArea`), `QMessageBox`, рамки выделения, некоторые системные подсказки — рисуются не по QSS, а по системной палитре. Если не задать `QPalette`, они останутся светлыми на тёмной теме.

Поэтому `apply_theme` делает три вещи:

```python
app.setPalette(build_palette(p))    # системная палитра
app.setStyleSheet(QSS)               # стили QSS
_paint_all_scrollareas(app)          # фон прокручиваемых областей
```

`build_palette` заполняет роли `QPalette`: `Window`, `Base`, `AlternateBase`, `ToolTipBase`, `Button`, `Light`, `Midlight`, `Dark`, `Mid`, `Shadow` получают `bg`, а текстовые роли (`WindowText`, `Text`, `ToolTipText`, `ButtonText`, `BrightText`) — `text`.

### Особый случай viewport

`_paint_all_scrollareas` обходит все `QAbstractScrollArea` в дереве виджетов и красит их через `paint_background`. Причина: QSS задаёт стиль самой прокручиваемой области, но её `viewport()` — отдельный виджет, который остаётся системного цвета. В комментарии указано, что пересказ темы сопровождался жалобами именно на это.

Исключение — область с именем `sidebarScroll`: у неё автозаливка **отключается**, потому что её фон рисуется градиентом в `mainRoot`, и заливка перекрыла бы градиент.

`walk` обходит детей рекурсивно, причём цикл выполняется дважды — второй проход нужен, чтобы вложенные области тоже получили цвет.

## Кеш цветов и доступ по токену

Помимо QSS, код часто нуждается в цвете как в объекте `QColor` — для `QPainter`, эффектов тени, иконок. Для этого есть `color(token)`:

```python
def color(token: str) -> QColor:
    cached = _COLOR_CACHE.get(token)
    if cached is None:
        cached = _make_color(token)
        _COLOR_CACHE[token] = cached
    return cached
```

`_make_color` различает три вида токенов:

- **прямые** — соответствие полю палитры (`bg`, `text`, `accent`);
- **с альфой** — `chart_fill_top`, `chart_fill_bottom`, `tooltip_bg`;
- **вычисляемые** — например `add_btn_border` через `_mix_hex`.

Кеш `_COLOR_CACHE` **очищается** в `apply_theme`. Это обязательный шаг: иначе после смены темы `color("accent")` вернул бы цвет прежней темы. Без очистки кеша смена темы давала бы «наполовину перекрашенное» окно — QSS обновился бы, а всё нарисованное вручную осталось бы старым.

`accent_alpha(alpha)` — отдельная функция для акцентного цвета с произвольной прозрачностью, используется в анимациях и подсветке.

## Глобальные переменные

Модуль держит набор модульных переменных, обновляемых в `apply_theme`:

```python
BG, SIDEBAR_TOP, CARD_TOP, ACCENT, CYAN, TXT, TXT2, TXT3
```

Они существуют для удобства горячих мест — обращения к ним дешевле, чем к `color(token)` с кешем. Недостаток очевиден: это глобальное состояние, и любой код, сохранивший ссылку на `ACCENT` до смены темы, будет использовать устаревший цвет. Поэтому в новых местах предпочтительнее `color(token)`.

## Предпросмотр темы в настройках

`SettingsPanel` показывает образец каждой темы через `_theme_sample(key, palette)` — небольшую панель с цветами темы.

Выбор темы применяется немедленно: `_pick_theme` испускает `theme_changed`, `MainWindow._preview_theme` вызывает `apply_theme`, и интерфейс перекрашивается на глазах.

Откат обеспечивается флагом `_committed`:

- при открытии запоминается `_theme_initial`;
- `close_requested` подключён к `_revert_if_cancelled`;
- в `_save` выставляется `_committed = True`;
- если панель закрыта без сохранения, `_revert_if_cancelled` возвращает прежнюю тему.

`_mark_theme_active` обновляет отметку выбранного образца.

## Иконка приложения

`load_app_icon()` пытается загрузить `assets/app_icon.ico`; если файла нет или иконка пуста, вызывается `make_clock_icon()`, которая рисует часы кодом в акцентном цвете текущей темы.

Путь к иконке вычисляется через `Path(__file__).resolve().parents[2] / "assets"`, что работает и при запуске из исходников, и в упакованной сборке, где `assets` добавлена через `--add-data`.

## Что важно помнить при правке

- `_COLOR_CACHE` должен очищаться при смене темы. Пропуск этой строки даёт частично перекрашенное окно.
- QSS и `QPalette` — две независимые системы. Правка только QSS оставит нативную прокрутку и `QMessageBox` в системных цветах.
- `sidebarScroll` намеренно исключён из `_paint_all_scrollareas`, потому что его фон — градиент.
- `soft()` инвертирует базовый цвет по `is_light`. Добавляя светлую тему, не надо переопределять эти токены вручную.
- Новый цвет вводится сначала как поле `Palette`, затем как токен в `_derive`, и только потом используется в QSS или через `color()`. Литералы в коде ломают смену темы.
- `_QSS_TEMPLATE` использует `string.Template`, поэтому `$` в шаблоне имеет специальный смысл.
